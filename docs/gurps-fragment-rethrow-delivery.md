# Fragment Luck after an armed grenade is thrown back

Basic Set Characters B66 permits Luck against an opponent's attack roll.
Campaigns B373 treats a thrown grenade as a ranged attack, B410 permits a witnessed
nearby delayed grenade to be recovered and thrown back, and B415 resolves the
resulting fragment attacks. The accepted later thrower is therefore the opponent
for a new fragment Luck opportunity after a canonical rethrow. The original
thrower cannot be substituted merely because the same warhead retains its first
blast identity.

The binder verifies both ends of the causal chain against accepted command history.
The original blast must have its canonical pending attack, exact newly added
schedule event and digest-verified producer receipt. A rethrow must add the exact
relocation event for its pending attack through an accepted canonical defense
input with the private `grenade-fuse` generation. The original blast identity,
source instance, encounter, payload, deadline and fuse dice remain unchanged.
The latest such delivery must continue the specifically named admitted launch.
Original-source claims after a later delivery and caller-supplied forged origin
identities are rejected before any blast or Luck dice.

The private captured launch keeps the latest pending attack identity and an
optional `origin_attack_id` for the original blast identity. The origin field is
omitted for ordinary launches and historical captured records. Replay consumes
its captured launch rather than rebinding it to later current custody or input.
No public command shape or historical accepted fact is rewritten.

Both-store host fixtures use actual opposing roles: A throws, B witnesses and
recovers the grenade, and B throws it back. A can then use Luck against B's
fragment roll, affecting the actual blast continuation. Restart, stale and
unauthorized choices, candidate rollback, exact retry, seed replay of preparation
and choice, and missing or changed provenance rejection are covered.

This bounded route covers an ordinary canonical defense producer for the later
throw. Repeated rethrows keep the latest such receipt. Replays of older inputs
without `grenade-fuse` retain their former scheduling behavior. Grenade catch,
airburst geometry, hot/incidental fragments, volatile secondary explosions and
spent-object burning chains remain unsupported. This is not full acceptance of
issue #869.
