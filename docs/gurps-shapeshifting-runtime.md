# Approved core form transformations

Characters third printing B83–85 distinguishes a replacement racial template from
an activation flag. Campaign-authored `alternate-form` and `morph` transformation
paths use the existing proposal, director approval, treatment, compilation and
resource-rebase lifecycle. The native approved build must purchase the matching
capability; authored template costs must agree with its parameters and the actual
build cost difference. Core paths retain the capability, ownership, identity and
history. They are voluntary, reversible and require ten seconds of treatment.
Modifiers require their own implementation and are rejected by this core path.

HP and FP deficits scale with the new form's maxima. Integer losses round up per
the Basic Set's general rounding convention. Injury and fatigue records remain
attached. A checkpoint returns an unconscious, dead or fatigue-collapsed active
form to the native approved build, preserving the disabling state. Morph pricing
is 100 points plus the positive template cost difference; Alternate Form retains
its distinct 90% premium calculation.

This is partial implementation evidence for #757. It does not certify the whole
family. Still required: timed voluntary reversion, mandatory authored external
reversion influence and its forced command, Morph seen/touched/memorized-form
eligibility and IQ-limited memory, interruption checks and complete gear-fit
handling. The standalone resource flag protocol rejects Alternate Form and Morph
so it cannot falsely report a successful transformation. Certification rows are
unchanged. #758 and #759 remain separate follow-on work.
