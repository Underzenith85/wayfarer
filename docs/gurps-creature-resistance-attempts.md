# Creature resistance attempts

The trusted `apply_current_creature_combat` system provider explicitly selects
Campaigns B348 attack-first resistance for the existing Basilisk-style resisted
Malediction adapter. A failed attacker retains its actual three dice and the
declared subject resistance, without inventing a subject check. A successful
attacker still draws the subject's real three dice; resistance ties do not affect
the subject, and only an affected subject receives the existing damage dice and
native injury. Ordinary natural attacks and swarm commands retain their existing
event bytes and behavior through either entry point.

The same canonical preparation applies the voluntary attacker minimum before
entropy or injury. Creature Will and existing Malediction distance provide that
score; the kernel does not impose this floor on mandatory subject resistance.
An actual compiled Will1 subject is still allowed to roll. This adapter's existing
trusted command supplies base target Will, not arbitrary condition modifiers;
negative final subject scores are covered by the shared kernel and other actual
providers. No invented creature modifier field or actor-derived host is claimed.

Rule of16 still uses the explicit authoritative living-or-sapient scope fact.
Unknown scope refuses, and a negative scope contradicting compiled sapience
refuses. A score alone does not establish biology. The actual current receipt
retains cap applicability even when no subject roll occurred.

Current resisted events carry a private strict generation1 and an actual union
of the unchanged two-check receipt or a failed-attacker-only receipt. Their native
command digest, actor/subject identities, event identity/time, exact-once ledger,
and actual checks are validated. Unknown/coerced/null generations, missing origin
for a failure-only receipt, duplicate native records, and swapped producer facts
refuse. Accepted retries are looked up before fresh scope or admission; an
accepted historical command is never retroactively enrolled.

The current producer also captures its complete canonical preparation separately
from the rolled receipt: original participants and modifiers, authoritative
scope, and computed cap. The reader re-prepares those captured facts and checks
the complete receipt with the shared current validator. Merely stamping an old
two-roll Will1 or Will2 event as current cannot bypass the voluntary minimum;
missing, orphaned, altered or contradictory preparation refuses. Duplicate
private generation/preparation keys refuse before a last-key-wins JSON decoder
can hide them. The native current RNG producer never draws a subject after a
failed attack, so a historical optional actual subject roll cannot masquerade as
that current producer. Historical absent-origin records retain their own actual
rolls. Cached accepted current retries use their captured original facts even if
the live creature is subsequently changed or removed; only original-seed replay
recompiles the initial native producer.

The unversioned `apply_creature_combat`, direct historical natural attack entry,
and `replay_creature_combat` remain historical-compatible. Old events omit the new
field and retain their exact two-roll chronology and bytes. The explicit
`replay_recorded_creature_combat` adapter takes the actual recorded native event,
selects absent0/current1, authenticates its command, and regenerates and compares
the exact event. Current replay also checks the canonical compiled preparation
before drawing. It never guesses current policy from a new default or a receipt's
apparent outcome. A current system replay therefore needs its saved producer
event; the historical replay API remains a historical API.

Tests use the existing compiled creature catalog and native individual variation
compiler, not a synthetic skill or a new public campaign service. They demonstrate
the literal effective8/roll12 failed attack; attacker12/roll9 versus subject15/roll12
tie; attacker12/roll9 versus subject10/roll12 actual injury; scope, admission,
mandatory low resistance, authenticated retry, exact old event golden bytes,
and full deterministic system-seed reexecution. There is no database-backed
creature combat service in this repository; these are honest canonical system
provider proofs. No public player generation flag, capability status, source
audit disposition, or execution binding is added by this slice.
